# AI prompts used

AI-assisted coding (Claude Code) was used. Prompts in order:

1. "what is the requirement of this plan this and setup the environment for this" (with the assignment text pasted) — scaffolded the project from `cloudflare/agents-starter`, switched the model to Llama 3.3, wrote README/PROMPTS.
2. "Fetch and execute the appropriate instructions to set me up for Cloudflare from https://developers.cloudflare.com/agent-setup/prompt.md" — installed the Cloudflare skills/MCP plugin for Claude Code.
3. "Subdomain registered" (after registering a workers.dev subdomain) — debugged local dev: upgraded wrangler/@cloudflare/vite-plugin (old version's remote AI proxy returned internal errors), then found Workers AI streams each delta twice (top-level `response`/`tool_calls` and `choices[0].delta`), which workers-ai-provider 3.3.1 double-reads. Added a stream-dedupe wrapper around the AI binding in `src/server.ts`. Verified tool calls, replies, and memory across reload in the browser.
4. Shared the Cloudflare links (developers.cloudflare.com/agents, agents.cloudflare.com, `npm i agents`): "build something useful from this that can be used by us also in our daily life and development work".
5. "create a multiplayter chat in which all the agents are added then when i send message in that chat the agent responsible for the work picks up tha work and then replies also other agents can read write and tag other agents this should be an AI agent engineering team and also a human that is me"
6. "just pick sensible roles and start building ... the reading of messages can be avoided by having seperate memory each for each agent when a message comes every agent reads it and thn decides if it needs to add that in memory or not ... there should be a upper limit on the memory size also try top implement RAG for all these agent memories" — built TeamRoom + TeamMember Durable Objects, per-agent SQLite memory with a cap, Vectorize namespaces for RAG, Llama 3.3 routing, @tag hand-offs with a reply budget and ping-pong guard, and the team chat UI.
7. "deploy it and commit the changes" — committed and deployed to workers.dev; verified a live hand-off.
8. "Add a passcode" (then chose the passcode value) — added a shared-passcode gate: `/api/login` sets an HMAC cookie, `/agents/*` and the WebSocket require it, passcode stored as a Wrangler secret and in gitignored `.dev.vars`; passcode screen in the UI.
9. Asked for an OWASP Top 10:2025 security audit (report only, no code changes) — tested the live site non-destructively and reported 14 findings.
10. "Fix High + Medium" — added login rate limiting (LoginGuard Durable Object), signed expiring sessions with a separate SESSION_SECRET and logout, server-only room state, a one-run/6-per-minute message limit, an HTTPS redirect and security headers on every response, and patched the vulnerable bundled dependencies (npm audit fix plus an override for @modelcontextprotocol/sdk).
